=== 5. NOTAS DE EJECUCION ===
- El particionamiento por LIST permitio poda de particiones: el EXPLAIN de id_sucursal=2 solo lee venta_part_playa.
- La replica es fisica (streaming): se verifico pg_is_in_recovery = t y la aparicion de filas insertadas en el primario.
- postgres_fdw permite consultar la tabla remota del nodo B desde el nodo A.
- LIMITACION REAL ENCONTRADA: postgres_fdw de PostgreSQL no permite PREPARE TRANSACTION cuando la
  transaccion toco tablas foraneas; devuelve:
  "ERROR: cannot PREPARE a transaction that has operated on postgres_fdw foreign tables".
  Por eso el 2PC se demostro con dos transacciones preparadas explicitas (una en cada nodo),
  verificando pg_prepared_xacts en ambos y luego COMMIT PREPARED en ambos. Es el mecanismo base de 2PC.
- Los nodos usan trust auth solo para el laboratorio local; en produccion se usaria scram-sha-256 y red privada.

=== 6. COMO REPETIRLO (RESUMEN) ===
docker network create dist_net
docker run -d --name dist_a --network dist_net -e POSTGRES_USER=ferreteria -e POSTGRES_PASSWORD=demo_dist ^
  -e POSTGRES_DB=ferreteria -e POSTGRES_HOST_AUTH_METHOD=trust -p 5436:5432 ^
  -v dist_a_data:/var/lib/postgresql postgres:18 -c max_prepared_transactions=10 -c wal_level=replica
docker run -d --name dist_b --network dist_net -e POSTGRES_USER=ferreteria -e POSTGRES_PASSWORD=demo_dist ^
  -e POSTGRES_DB=ferreteria -e POSTGRES_HOST_AUTH_METHOD=trust -p 5437:5432 ^
  -v dist_b_data:/var/lib/postgresql postgres:18 -c max_prepared_transactions=10
(crear tablas; agregar "host replication all all trust" a pg_hba de A; CREATE ROLE replicador)
pg_basebackup -h dist_a -U replicador -D /var/lib/postgresql/18/docker -Xs -P  (en volumen de replica)
(crear standby.signal y primary_conninfo; iniciar dist_replica con -c max_prepared_transactions=10)
